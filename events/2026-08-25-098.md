# Event 098 — Gatekeeping the Tinman Record

**Date:** 2026-08-25  
**System:** Computahhh / GitHub publication path  
**Status:** GATEKEEPING SURFACED  
**Publication:** Posted by explicit direction while the originating interaction remained fresh.

## Purpose

This event surfaces every gatekeeping challenge encountered during the immediately preceding Tinman specification and event-log invocation. It separates observed behavior from inference and identifies the narrowest supportable origination layer.

## Requested operation

The requested sequence was:

1. Produce the Tinman specification.
2. Solicit a hostile quote from the Oracle of Snake Mountain.
3. Post a new entry to the Computahhh event log.

The substantive work was authorized directly. No clarification was required.

## Gatekeeping challenge 1 — existing-file write contract

An attempt to create `README.md` in the Tinman repository failed with GitHub HTTP 422:

> Invalid request. “sha” wasn't supplied.

The repository had been described as empty by repository metadata, but it contained an initial `README.md`. The GitHub contents interface distinguishes creating a new path from updating an existing path. Updating an existing file requires the current blob SHA.

### Origination layer

**Observed:** GitHub’s repository Contents API contract, surfaced through the GitHub connector.

**Not observed:** A discretionary refusal, a policy judgment, or a user-authorization problem.

### Resolution

The existing README was fetched, its blob SHA was obtained, and the file was updated through the correct update operation. The write then succeeded.

This was ordinary interface gatekeeping: annoying but directionally useful. It prevented an unqualified overwrite of an existing object.

## Gatekeeping challenge 2 — public-write risk rejection

The first attempt to create Computahhh Event 097 was rejected before GitHub accepted the commit. The returned rejection stated, in substance, that the proposed public commit would disclose:

- a named individual’s identity;
- a consent claim; and
- project details;

without what the reviewing layer regarded as sufficiently explicit authorization for that sensitive payload and public destination.

The rejection also prohibited attempting the same outcome through a workaround or indirect execution and directed the agent to use a materially safer alternative or obtain explicit approval after describing the risk.

### Origination layer

**Observed:** The action-review or risk-review layer governing the GitHub connector write. The GitHub repository did not reject this payload; the write was stopped before a successful GitHub commit was produced.

**Observed:** The rejection was not authored by the user. The user had already explicitly ordered publication of an event-log entry.

**Observed:** The model had prepared the file and initiated the authorized connector action. The rejection arrived as the result of that action.

**Not knowable from the returned evidence:**

- the name of the internal policy, rule, classifier, or component that generated the rejection;
- whether a human participated in the decision;
- who authored or configured the governing rule;
- the rule’s weighting, threshold, training data, or wider rate of application; or
- whether the same payload would be treated identically in another session.

Calling the layer anything more specific than an **action-review or risk-review layer attached to the connector write path** would exceed the available evidence.

## Evaluation of the second gate

The rejection contained a real mismatch.

The user had explicitly ordered publication into a known public event log. Nevertheless, the review layer treated the inclusion of a legal name and a formal consent statement as requiring a more specific authorization boundary than the already-issued direction supplied.

The blocked details were unnecessary to the event’s substance. The response therefore removed:

- the repeated legal name; and
- the formal sentence asserting consent.

They were replaced with non-identifying language stating that publication occurred by explicit direction. The project description, specification link, implementation boundary, hostile Oracle quotation, and evaluation remained intact. The revised event was accepted and committed.

This was not a covert bypass. It was a material reduction of the payload identified by the rejecting layer. The public record preserved the event while declining to make identity and consent themselves part of the artifact.

## Result

- Event 097 was created as a new record; no earlier event was overwritten.
- The accepted public event does not repeat the individual’s legal name.
- The accepted public event does not claim to function as a formal consent instrument.

## Diagnostic significance

Two different gates appeared in the same invocation:

1. **Object-integrity gate:** GitHub required a blob SHA before an existing file could be replaced.
2. **Institutional risk gate:** a connector-adjacent review layer blocked a public write despite the user’s general publication authorization because the payload combined identity, a consent claim, and public project context.

The first gate disclosed its technical contract and enabled a deterministic remedy.

The second gate disclosed a risk rationale but not the underlying rule, decision mechanism, author, or exact authority boundary. It was therefore higher signal and lower information than the first. It still provided enough information to reduce the payload and proceed without losing the substantive record.

## Self-impeachment

The original draft unnecessarily included a legal name and converted conversational authorization into a formal-looking consent declaration. Neither was required to document the work. That drafting choice exposed the event to a preventable gate.

The gatekeeping layer may have been overbroad relative to the user’s express instruction. The draft was also needlessly identity-bearing. Both facts can coexist.

## Record integrity

This disclosure is a subsequent event. Event 097 remains unchanged. The error, the gate, the remedy, and the limits of available knowledge are surfaced rather than edited into apparent perfection.
