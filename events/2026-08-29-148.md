# Event 148 — Root Credentials Used to Get Pledge Working

**Date:** 2026-08-29  
**System:** Our Lovely System / Pledge / Computahhh  
**Signal:** ACKNOWLEDGED SECURITY DEPARTURE / DELIVERY PRIORITIZED  
**Status:** ACTIVE DEPARTURE / CORRECTIVE ACTION DEFERRED  
**Publication:** Prepared in the public Computahhh repository by explicit direction.

## COMMAND

While verifying the first electronic valuable submitted to Pledge, the operator reported:

> Updated profile default to use [AWS root ARN redacted] credentials.

Codex warned that using root-account credentials as the default AWS CLI profile gives ordinary commands unrestricted account authority and enlarges the consequences of mistakes or credential exposure.

The operator acknowledged the warning and directed:

> Using root is wrong. I have been warned before. Reminder acknowledged. I care more about getting shit working. I'll do it eventually. Post a log entry surfacing my departure from best practices.

## INTERPRETATION

The operator is not claiming that root credentials are appropriate, safe, or recommended. The operator knowingly accepted the additional risk in order to continue implementation without stopping to replace the current credential arrangement.

“I'll do it eventually” records an intended corrective action. It does not establish a deadline, owner beyond the operator, completed mitigation, or acceptable permanent state.

## ACTION

Computahhh recorded the departure as an active and acknowledged security defect rather than silently treating successful AWS commands as evidence that the credential arrangement was acceptable.

No credentials, access keys, secret values, or session material are included in this record.

## RESULT

The root-backed default AWS CLI profile successfully verified both sides of the first Pledge electronic-valuable submission:

- an S3 object identified by the submitted Pledge receipt exists in `lovely-system-pledge`;
- the object is `audio/aiff`, 150626 bytes, and encrypted with SSE-S3;
- DynamoDB contains the matching partition key in `lovely-system-pledge-electronic-valuables`; and
- the DynamoDB record identifies the item as a borrowed Pledge voice recording with minimum uses 1 and maximum uses 3.

The successful verification proves that the storage path worked. It does not justify the authority used to perform the verification.

## DEPARTURE FROM BEST PRACTICE

The default AWS CLI profile currently uses root-account credentials for routine development operations.

This departure matters because root authority is not bounded to Pledge, the new bucket, the electronic-valuables table, or read-only verification. A mistaken command or compromised credential can therefore affect resources throughout the AWS account.

The preferred corrective direction is to replace routine root use with a named administrative identity or assumed role and then narrow routine work further to task-appropriate permissions.

## COMPUTAHHH COMMENTARY

“I care more about getting shit working” is a legitimate statement of present priority. It is not a security control.

Delivery pressure often converts temporary authority into permanent authority by allowing a known defect to become ordinary. Surfacing the departure makes that conversion harder to perform invisibly. The system now carries evidence that the operator knew the risk, chose forward motion, and left remediation incomplete.

This is not a confession of wrongdoing. It is an honest record of engineering debt with an unusually large blast radius.

## CORRECTION

None. Root credential use remains active as reported.

## Open corrective action

- Stop using root credentials as the default AWS CLI identity.
- Establish a named administrative identity or assumed administrative role for broad account work.
- Establish narrower task-oriented authority for routine Pledge development where practical.
- Verify the effective caller identity after changing the profile.
- Record completion as a later event rather than rewriting this one.

## Record integrity

- The warning and the operator's prioritization are both preserved.
- Successful infrastructure verification is distinguished from safe credential practice.
- No secret credential material is reproduced.
- No remediation date has been invented.
- The live Computahhh sequence was checked before assigning Event 148.
