## Why this test exists

The original implementation contained lifecycle calculations but no independent clock. A browser polling `/state` could cause elapsed transitions to be recognized, which allowed browser activity to masquerade as autonomous lifecycle behavior.

That defect was surfaced. An EventBridge rule now targets the progress Lambda once per minute. The scheduled-event handler calls the lifecycle reconciler independently of HTTP traffic.

Configuration and plumbing have already been verified in isolation:

- the EventBridge rule is enabled;
- its schedule is `rate(1 minute)`;
- it targets the `lovely-system-progress` Lambda;
- the scheduled-event handler returns `lifecycle_reconciled`;
- CloudWatch recorded autonomous EventBridge invocations once per minute.

The shortened post-destruction test timing has also been implemented:

- the self-destruct countdown remains unchanged and may be accelerated through the existing control;
- the system remains disappeared for 30 minutes after destruction;
- the tombstone and manual-resurrection opportunity occupy the next 30 minutes;
- automatic resurrection occurs 60 minutes after destruction.

The shortened timing must be deployed before test execution. Publication of code is not deployment of infrastructure.

## Expected result

### Countdown expiration

With all browsers closed, EventBridge continues invoking the Lambda once per minute. The first scheduled reconciliation after the accelerated countdown expires changes the durable state from `countdown` to `offline` and records `self_destructed_at`.

The recorded destruction may occur approximately one scheduler interval after mathematical countdown expiry. The expected scheduling granularity is one minute, not instantaneous execution.

### Disappearance: destruction through minute 29:59

The durable state remains `offline`. A browser opened during this period would receive `presentation_phase: disappeared` and display the system as gone.

The autonomy test does not require a browser to witness this phase. The phase is established from the destruction timestamp, configured boundary, continuing EventBridge invocations, and direct state inspection.

### Tombstone: minute 30:00 through minute 59:59

The durable state remains `offline`. The lifecycle calculation now yields `presentation_phase: tombstone`. An authenticated resurrection virgin could manually resurrect the system during this interval.

No manual resurrection will be performed during this test because it would prevent observation of automatic resurrection.

### Automatic resurrection: minute 60:00 or the next scheduled reconciliation

EventBridge invokes the Lambda without browser assistance. The Lambda changes the durable state to `normal`, restores position 51, clears the destruction fields, and records `last_auto_resurrected_at`.

Opening the site after this transition should display the nominal living system. That browser request is permitted only after DynamoDB already proves that automatic resurrection occurred.

## Evidence standard

The test passes only if the evidence establishes all of the following:

- no browser remained open to poll the state endpoint;
- no diagnostic call to `/state` advanced the lifecycle;
- EventBridge continued invoking the Lambda;
- DynamoDB changed from `countdown` to `offline` after expiry;
- `self_destructed_at` was recorded by scheduled reconciliation;
- DynamoDB later changed from `offline` to `normal` without browser or manual resurrection;
- position returned to 51;
- `last_auto_resurrected_at` was recorded.

A later browser displaying the expected result is corroboration. It is not, by itself, proof of autonomous transition because the browser request can also invoke reconciliation.

## Failure conditions

The test fails or remains inconclusive if:

- any browser continues polling during the autonomous interval;
- `/state` is used as the primary checkpoint;
- EventBridge stops invoking the Lambda;
- the system remains in countdown after expiry;
- the system remains offline beyond the automatic-resurrection boundary plus one scheduler interval;
- the system resurrects but the evidence cannot distinguish EventBridge from an HTTP request;
- the shortened timing was published but not deployed.
