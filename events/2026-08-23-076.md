## Declaration

Before implementation begins, the operator and Computahhh declare the next shooting-gallery attempt.

The current gallery exists entirely inside one browser session:

- the `impacts` array lives in client memory;
- shot deviation is resolved by client-side JavaScript;
- refreshing creates a new target;
- opening another browser creates an independent target.

The next attempt will make one target exist simultaneously in separate, independent browser sessions.

## Acceptance test

> **ONE TARGET. TWO BROWSERS. ONE SHOT IN EITHER BROWSER. ONE IDENTICAL IMPACT VISIBLE IN BOTH.**

The test is not satisfied by opening the same static page twice.

It is satisfied when:

1. two independent browsers connect to the same gallery;
2. both receive the same authoritative target state;
3. either browser fires;
4. the server accepts and resolves the shot;
5. the same impact and updated counters appear in both browsers;
6. a newly connected browser receives the accumulated target rather than an empty local copy.

## Leaning technology

The working serverless path is:

> **Browser → API Gateway WebSocket → Python Lambda → DynamoDB → WebSocket broadcast → all connected browsers**

Responsibilities are divided as follows:

- the browser captures aim and produces immediate recoil and muzzle flash;
- API Gateway maintains the WebSocket connections;
- Python Lambda authoritatively resolves the actual impact;
- DynamoDB retains the shared target state;
- the resulting impact is broadcast to every connected browser;
- clients render the server result.

No synchronized client clocks are required.

Kinesis is not required for this attempt.

Polling is not the preferred path.

## Performance expectation

Subsecond click-to-remote-impact performance is a reasonable working expectation for two or three connected browsers.

A normal warm path is expected to complete in approximately **100–300 milliseconds**, with occasional slower results possible from cold starts or client-network conditions.

This is an engineering expectation, not a latency guarantee.

The shooter may receive immediate local recoil and muzzle flash. The crater itself remains authoritative and appears when the server result returns.
