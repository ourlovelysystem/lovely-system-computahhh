# Event 095 — Protected Page Flashes During Refresh

**Date:** 2026-08-24  
**System:** Our Lovely System — Shared Lifecycle Presentation  
**Affected surface:** Teambuilder / Yellow Lion  
**Signal:** DEFECT / PRESENTATION LEAK  
**Status:** OPEN / OBSERVED DURING ACTIVE TEST

## Defect

While the system was in the disappeared phase, refreshing the Yellow Lion page briefly exposed the original application before the shared “Not Found” presentation returned.

The protected page therefore becomes visible for a fraction of a second during reload.

## Expected behavior

When the authoritative lifecycle state requires disappearance, the original application must not become visible at any point during initial load or refresh.

The disappearance presentation should cover the page before protected content can paint and should remain in place until the current lifecycle state has been resolved.

## Observed behavior

The operator captured two successive views:

1. the full-viewport “Not Found” disappearance presentation;
2. the underlying Yellow Lion page visible during refresh.

The underlying page included the parked Yellow Lion presentation and its application controls. Its visibility was brief but perceptible.

This is a flash-of-original-content defect. The full-viewport geometry repair succeeded once the shared presentation was active, but activation occurs too late to prevent the host page from painting first.

## Sanitization

The supplied screenshots are intentionally **not embedded or published** with this event.

Their browser chrome contained unrelated tab information, account indicators, system-status information, timestamps, and thumbnail content outside the defect boundary. Those details are unnecessary to establish the defect and have been excluded.

The retained evidence is limited to this sanitized observation:

> During refresh of the Yellow Lion page while the system was disappeared, the full original application became visible briefly before lifecycle presentation control resumed.

No unrelated browser or account information is reproduced in this record.

## Preliminary technical evaluation

The defect is consistent with the shared lifecycle script applying the disappearance overlay only after the host document has rendered and the lifecycle state request has completed.

That is a hypothesis, not yet a confirmed root cause.

A durable repair likely requires a fail-closed loading boundary: participating pages should begin visually concealed or covered, load the lifecycle controller as early as possible, and reveal the application only after the controller confirms that presentation is permitted.

The repair must also define failure behavior. A slow or failed lifecycle request must not silently expose content if the intended contract is disappearance-first.

## Test impact

This defect does not invalidate the already completed infrastructure precondition checks.

It is, however, a relevant finding during the active lifecycle test and prevents a clean pass for disappearance presentation on refresh. A page that becomes visible briefly is not fully disappeared.

The remainder of the lifecycle test may still produce useful evidence for tombstone timing and automatic resurrection. Those results should be evaluated separately from this presentation defect.
