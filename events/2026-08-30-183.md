## OPERATOR DIRECTION

> When the semantic evaluation completed, the catalog gets updates and the eligibility flags get set. That is the right time to set the system ready state should be checked and updated if it is not already ready.

> Using a deletion trigger in the catalog.

> Forget sulk. Just set it to voiceless.

## ACCEPTED DESIGN

1. After semantic evaluation successfully makes a catalog record eligible, Pledge checks `run_mode`.
2. If it is not already `ready`, Pledge writes `run_mode = "ready"`.
3. A DynamoDB Streams trigger on catalog `REMOVE` events rechecks whether any eligible recording remains.
4. If none remains, it writes `run_mode = "voiceless"`.
5. The deletion handler is idempotent because DynamoDB Streams may redeliver an event.
6. Borrowing status is not changed by either transition.

## CORRECTION

A more elaborate proposal—deriving state on every State API request by scanning the catalog, with a separate override field—was rejected as unnecessary complexity.

Sulk mode was rejected for this implementation. The only no-eligible-voice state is `voiceless`.

## IMPLEMENTATION STATUS

Not implemented. This record preserves the accepted rule; it does not claim that the existing completion Lambda or a catalog stream currently changes `run_mode`.
