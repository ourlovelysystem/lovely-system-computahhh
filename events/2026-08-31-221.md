# Event 221 — Pledge Door Response Reaches Transcribe; Completion Stage Is Absent

**Date:** 2026-08-31  
**System:** Pledge  
**Signal:** TEST RESULT / IMPLEMENTATION GAP  
**Author:** Codex (OpenAI), recording operator-performed tests and AWS outputs supplied by Will D.

## Operator test

Will tested `https://pledge.ourlovelysystem.org/door.html` after the browser MIME normalization and S3 CORS work. The page displayed: “Pledge received the response. Transcription continues after you leave this page.”

The interface was described by Will as busy. No visual revision was made in this event.

## Evidence and result

The initial new session reached `upload_pending`, while its S3 recording object was absent. Investigation established that bucket `lovely-system-pledge` had no CORS configuration. Codex directed a narrowly scoped CORS rule permitting `PUT` with `Content-Type` from `https://pledge.ourlovelysystem.org`.

After that change, a new test session (`f171bd1e-81f7-42b1-90ec-811f1b5d6318`) showed:

- `audio_content_type: audio/webm`
- `status: submitted`
- a Transcribe job: `pledge-door-f171bd1e-81f7-42b1-90ec-811f1b5d6318`
- Amazon Transcribe status: `COMPLETED`, with no failure reason.

This proves the browser challenge, microphone capture, presigned S3 upload, submit API, and Transcribe job creation/completion path.

## What failed / remains unimplemented

The same DynamoDB session still had `status: submitted` after Transcribe completed. It contained no transcript or completion fields.

Will ran `aws lambda list-functions` for names containing `door`. The only deployed function was `lovely-system-pledge-door-sessions`. There is no deployed door-session completion Lambda. The existing catalog transcription-complete Lambda does not accept `pledge-door-<UUID>` job names.

Therefore this is not evidence that Pledge's voice gate is complete. The final asynchronous stage has not been implemented: a dedicated door-session completion handler and its Amazon Transcribe completion EventBridge rule must persist the result. The later decision that grants `isNotMute=true` also remains unimplemented.
