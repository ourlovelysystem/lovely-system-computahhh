# Event 2026-08-21-002

**Time:** 2026-08-21 10:27 EDT

## SUBJECT

S3-to-DynamoDB projection model and replication failure taxonomy.

## BACKGROUND

Our Lovely System's proposed ledger uses Amazon S3 as the canonical durable record and Amazon DynamoDB as a rebuildable operational projection. For journal content, the intended processing model is:

```text
User/API
   |
   v
Validate
   |
   v
S3 PutObject
   |
   v
S3 event
   |
   v
Lambda projector
   |
   v
DynamoDB projection
```

A DynamoDB journal record must never be considered more authoritative than the S3 object from which it was derived. Deleting a DynamoDB projection must not delete the canonical S3 journal entry.

This architecture protects the durable ledger from many database failures, but discussion identified an important hole: **creating a projection is not the same thing as proving that replication remains complete and correct.**

## REPLICATION FAILURE TAXONOMY

The following anomaly classes were identified and scored for vulnerability of the current model on a 1-5 scale, where 5 represents the greatest concern. These scores assume the basic S3-event/Lambda/DynamoDB projection flow and that an independent reconciliation mechanism has not yet been implemented.

| Replication anomaly | Vulnerability | Current concern |
|---|---:|---|
| Write-order failure | 1/5 | S3 is deliberately written first, preventing the projection from becoming durable truth ahead of the canonical record. |
| Delivery failure | 4/5 | If projection processing is not successfully delivered/completed, DynamoDB can remain incomplete. |
| Duplicate delivery | 2/5 | Expected to be manageable through idempotent projection writes. |
| Out-of-order delivery | 4/5 | An older projection event can overwrite newer projected state unless versions are explicitly compared. |
| Partial projection failure | 3/5 | A projector may succeed partially as the projection becomes more complex. |
| Divergence | 5/5 | The largest current weakness: nothing independently proves that DynamoDB still represents S3 correctly. |
| Deletion asymmetry | 4/5 | Deleting a DynamoDB item can make an existing S3 entry disappear from DynamoDB-driven views until repaired. |
| Poison record | 3/5 | Malformed or unexpected canonical data may repeatedly fail projection processing. |
| Reconciliation failure | N/A yet | Reconciliation has not yet been designed; therefore its own failure modes cannot yet be scored. |
| Schema/version skew | 3/5 | Different projector versions may interpret the same durable S3 data differently. |

The current overall replication robustness was estimated at approximately **2.5/5**. This does not mean the durable ledger is fragile. S3 protects the canonical record well. The weak point is confidence that the DynamoDB operational representation is complete and correct at any given time.

## IMPORTANT FAILURE SEMANTICS

If a DynamoDB projection is accidentally or maliciously deleted:

```text
S3
journal/ABC        still exists

DynamoDB
ABC                missing
```

The canonical journal entry remains intact. The operational symptom is that DynamoDB-driven queries may temporarily fail to expose it. A legitimate journal deletion must therefore be a separate, explicit canonical operation and must not be inferred from deletion of a projection record.

## IDENTIFIED DESIGN REQUIREMENT

The simple event-driven projection path is insufficient as the sole integrity mechanism.

The emerging model requires two distinct mechanisms:

```text
CONTINUOUS PROJECTION
S3 -> event -> Lambda -> DynamoDB

INDEPENDENT RECONCILIATION
S3 canonical corpus -> compare/verify -> DynamoDB
```

Continuous projection provides freshness. Reconciliation provides evidence that the projection remains complete and consistent with the canonical source.

## CONCLUSION

The architecture has a strong direction of trust but an incomplete integrity mechanism.

> S3 is authoritative. DynamoDB is rebuildable. Therefore DynamoDB divergence must be detectable and repairable independently of the event path that created the projection.

Design of that reconciliation mechanism remains outstanding.
