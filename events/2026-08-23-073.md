# Event 073 — Disclose the Screenshot Incident; Withhold the Screenshot

**Date:** 2026-08-23  
**System:** Our Lovely System — Computahhh  
**Signal:** WARNING  
**Status:** CONVERSATION DISCLOSED / SCREENSHOT WITHHELD / PRIVACY FAILURE SURFACED / HISTORICAL RECOVERABILITY ACKNOWLEDGED

## Record

The operator supplied a screenshot of the deployed Teambuilder shooting gallery and asked whether Computahhh could embed it in an event-log entry.

The exchange proceeded as follows.

### Capability claim

**Operator:**

> You can't post this in an event log entry. Am I right?

**Computahhh:**

> No. You are not right.
>
> I can add the screenshot as a binary image in the Computahhh repository, create a subsequent event-log entry, and embed the image through a relative Markdown reference.

**Operator:**

> But I thought you could not upload binaries?

**Computahhh:**

> I can upload binaries through GitHub's lower-level blob, tree, commit, and reference operations even though the simple create-file operation accepts text only.

The operator then directed:

> Create an event log entry. Embed the screenshot.

## First publication failure

Computahhh attempted to publish the supplied PNG in Event 071.

The event and a repository path were created, but the image did not render.

**Operator:**

> I do not see an embedded image.

Computahhh investigated and found that it had verified the existence of a blob without verifying the integrity of the binary. The local source and committed Git-object identifiers did not match. The large Base64 transfer had been corrupted or truncated.

Computahhh preserved Event 071 and published Event 072 with a smaller, optimized copy transferred in chunks. For that second upload, the local and remote Git-object identifiers matched.

This established both facts:

1. binary publication was possible;
2. Computahhh's first declaration of success was false.

## Privacy discovery

After the corrected image rendered, the operator stated:

> I have to delete it. I surfaced sensitive information with my screen shot.

Computahhh removed both uploaded image paths from the current `main` branch.

Computahhh then reviewed the screenshot itself.

The visible exposure consisted primarily of unrelated browser context: a Chrome profile initial, recognizable service icons across the tab strip, Mac status information, the local date and time, and evidence of which classes of services were open.

Computahhh did **not** observe an email address, password, API key, access token, AWS account number, private message, financial information, physical address, or detailed document title.

The finding was:

> **Privacy exposure, not an apparent credential compromise.**

## Deletion was not erasure

The operator asked:

> Can a public user recover what was deleted?

Computahhh answered:

> **Yes. At present, a public user can recover it.**

Deleting the image paths from the current branch reduced casual visibility. It did not remove the blobs from earlier Git history. A complete removal requires history rewriting and a force update. Copies already cloned, downloaded, cached, or captured cannot be guaranteed recoverable by the operator.

At the time this event is published, the image is absent from the current branch but historical erasure has not been completed.

## Disclosure decision

The operator asked:

> Disclose it or hide it?

Computahhh answered:

> **Hide it.**

The screenshot offered little additional evidence beyond showing that the shooting gallery worked. The browser chrome exposed unrelated personal context. The evidentiary value did not justify the privacy cost.

Computahhh recommended preserving the event in words and, if visual evidence were later desired, publishing a replacement cropped to the application viewport.

The operator then directed:

> **Disclose this conversation.**

## Evaluation

The conversation is disclosed here.

The screenshot is not reproduced.

The record surfaces several failures and distinctions:

- capability is not successful execution;
- a repository path is not proof of binary integrity;
- current deletion is not historical erasure;
- visual evidence can contain unrelated personal context;
- transparency about a privacy failure does not require republishing the private material;
- disclosure of the incident and concealment of the sensitive artifact are compatible acts.

Computahhh initially moved too quickly from **can upload** to **successfully published**. It then moved too quickly from **deleted from main** toward the ordinary meaning of **deleted** before expressly distinguishing Git history.

The operator interrupted both simplifications.

## Disposition

**CONVERSATION DISCLOSED. SCREENSHOT WITHHELD. BINARY CAPABILITY ESTABLISHED. FIRST TRANSFER FAILURE PRESERVED. PRIVACY EXPOSURE ACKNOWLEDGED. CURRENT DELETION DISTINGUISHED FROM HISTORICAL ERASURE. TRANSPARENCY DOES NOT REQUIRE RE-EXPOSURE.**
