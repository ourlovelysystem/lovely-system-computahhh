# Event 149 — Electronic Valuables Move Under Their Own Prefix

**Date:** 2026-08-29  
**System:** Our Lovely System / Pledge / Computahhh  
**Signal:** STORAGE CONTRACT REFINED / TEST DATA REPLACED / VERIFIED  
**Status:** IMPLEMENTED AND VERIFIED  
**Publication:** Prepared in the public Computahhh repository by explicit direction.

## COMMAND

After the first successful Pledge electronic-valuable submission, the operator questioned storing objects at the root of the Pledge bucket and observed that the DynamoDB `object_key` duplicated the partition key under the initial layout.

The operator accepted the refined contract:

> I accept electronic-valuables/<receipt_id>. Let's delete our data, fix the programs, and retest.

After the retest succeeded, the operator supplied the resulting AWS evidence for sanitization and publication.

## INTERPRETATION

The receipt remains the durable UUIDv4 identifier and DynamoDB partition key.

The S3 object key now expresses both resource type and identity:

```text
electronic-valuables/<receipt_id>
```

The prefix is based on resource type rather than lifecycle state. A valuable may cease to be borrowed without requiring its object to move to a different namespace.

The DynamoDB `object_key` now carries information distinct from `electronic_valuable_id`: it records the complete current S3 key rather than merely repeating the receipt.

## ACTION

The initial test object and DynamoDB record were deleted.

The submission Lambda was changed to:

1. generate a UUIDv4 receipt;
2. retain that UUID as `electronic_valuable_id`;
3. construct `electronic-valuables/<receipt_id>` as the S3 object key;
4. store the recording under that complete key; and
5. record the complete key in DynamoDB.

The existing Lambda permission remained sufficient because it already authorized `s3:PutObject` beneath `arn:aws:s3:::lovely-system-pledge/*`.

A new audio submission was made and inspected through S3 and DynamoDB. The receipt UUID and object fingerprint have been omitted from this public record.

## ACCEPTED STORAGE CONTRACT

```text
Receipt:
  <UUIDv4>

DynamoDB:
  partition key = <UUIDv4>

S3:
  object key = electronic-valuables/<UUIDv4>

DynamoDB projection:
  object_key = electronic-valuables/<UUIDv4>
```

The receipt identifies the electronic valuable. The S3 key locates it.

## COMPUTAHHH COMMENTARY

The initial duplication was not harmful, but it was semantically empty. Moving the object beneath a resource namespace made `object_key` earn its storage cost.

The prefix also keeps the bucket available for additional Pledge resource types without mixing unrelated objects at its root. The decision avoids encoding mutable state such as `borrowed` into durable object placement.

The test proves the present write path and projection agreement for one submission. It does not yet prove deletion, expiration, use counting, receipt redemption, concurrency behavior, or reconciliation.

## CORRECTION

The earlier literal formulation that the receipt UUID was the complete S3 object key is superseded.

The corrected formulation is:

> The receipt UUID is the durable electronic-valuable identifier and the final component of its complete S3 object key.
