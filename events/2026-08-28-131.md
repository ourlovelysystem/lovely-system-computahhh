# Event 131 — Traceable requirements for the Pledge state table

**Date:** 2026-08-28  
**Participants:** Will Daly; ChatGPT/Codex  
**Record type:** Requirements record  
**Status:** Recorded at Will Daly's direction

## Context

Will Daly defined a DynamoDB table for Pledge state records and requested a requirements assertion. ChatGPT/Codex initially added requirements concerning attribution, transition history, access patterns, privacy, resource naming, and architectural authority that Will had not stated.

Will responded:

> Your requirements took too many liberties.

ChatGPT/Codex acknowledged the unsupported additions and removed them. Will then directed:

> Present requirements which are traceable to my statement. Include my statement in your presentation.

## Source statement

> I want a Dynamo DB Table. This table will be for Our Lovely System - Pledge state records. run state will be among these but it will also include aggregate metrics which will be consumed by a conceived status page.

## Traceable requirements

| ID | Requirement | Source language |
|---|---|---|
| PLEDGE-STATE-001 | The system shall include a DynamoDB table. | “I want a Dynamo DB Table.” |
| PLEDGE-STATE-002 | The table shall contain state records for Our Lovely System — Pledge. | “This table will be for Our Lovely System - Pledge state records.” |
| PLEDGE-STATE-003 | The state records shall include run state. | “run state will be among these” |
| PLEDGE-STATE-004 | The state records shall include aggregate metrics. | “but it will also include aggregate metrics” |
| PLEDGE-STATE-005 | The aggregate metrics shall be consumable by a conceived status page. | “which will be consumed by a conceived status page.” |

## Boundary

No requirement is asserted here for table keys, indexes, record shapes, update authority, transition history, attribution, privacy, public access, consistency, retention, resource naming, or whether DynamoDB is canonical or projected storage. Those matters were not specified in the source statement.
