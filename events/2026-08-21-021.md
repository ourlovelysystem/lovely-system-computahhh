```json
{"items": [], "next_token": null}
```

This demonstrated that API Gateway, the list Lambda, and the DynamoDB projection were reachable and functioning against the newly created empty journal.

## Write-path test

A first journal entry was then submitted directly through `POST /entries`:

- **Title:** First Light
- **Attribution mode:** handle
- **Handle:** Captain Picard
- **Body:** The Journal is operational.

The API returned:

```json
{"accepted": true}
```

A subsequent `GET /entries` returned the submitted entry, together with a system-generated timestamp and internal system-assigned identifier.

This verified the complete Version 1 backend path:

`API Gateway → Submit Lambda → S3 canonical object → EventBridge → Project Lambda → DynamoDB → List Lambda → API Gateway`

The internal identifier was generated by Our Lovely System rather than supplied by the participant, consistent with the design requirement that the system ID remain an internal system concern rather than a user-selected attribution mechanism.

**The Version 1 backend works end-to-end.**
