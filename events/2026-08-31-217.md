## EXCHANGE, TRACED

Claude's first recommendation proposed anchoring hashes of events on-chain while keeping the actual content in the existing git repository — treating durability as solved by tamper-evidence. The operator identified the flaw directly: a hash proves nothing about content that no longer exists anywhere to check it against. Integrity and durability are different properties, and the recommendation had conflated them.

The operator then stated the actual requirement precisely: the record must survive the author. That constraint rules out any solution depending on continued action by a living person — renewed hosting payments, refreshed mirrors, a maintained wallet. Under that constraint, storing the content itself on infrastructure funded by a one-time payment rather than ongoing maintenance became the right structural fit, with Arweave named as the purpose-built example: a one-time payment funding a network-level endowment intended to keep storing data indefinitely without further action from the depositor.

Asked to compare popular blockchains against the purpose-built one across initial cost, ongoing cost, data size limits, and inspectability, Claude searched for current figures rather than stating remembered numbers, given their volatility and the session's own standard against unverified specifics.

## FINDINGS

| | Bitcoin | Ethereum | Solana | Arweave (purpose-built) |
|---|---|---|---|---|
| Initial cost | ~$0.50–$50 for an 80-byte `OP_RETURN` payload depending on congestion; the 80-byte cap was removed in Bitcoin Core 30 (Oct 2025), allowing larger payloads at proportionally higher fees | ~$460/MB at recent calldata pricing (12 gwei, $2,300/ETH) — a volatile snapshot, not a constant | ~6.96 SOL/MB, paid once as rent-exemption | ~$0.008/MB, roughly four to five orders of magnitude cheaper than Ethereum calldata for the same byte |
| Ongoing cost | None beyond the transaction fee | None beyond the transaction fee | None while rent-exempt, but an account can be closed and its storage reclaimed if its balance is later drained | None — funded by a network-level endowment rather than the depositor's continued action |
| Data size limits | Formerly capped at 80 bytes; now up to ~4MB per output per the 2025 change, with uncertain consistency across node implementations this soon after the change | No hard protocol cap; limits are economic, not technical | An account-size cap exists; the exact figure was not stated with confidence rather than guessed | No meaningful practical limit for a text log; large files are chunked by the protocol |
| Inspectability | Fully public, plain bytes, standard tooling | Fully public via any node or explorer | Public via Solana explorers, requiring more Solana-specific tooling | Public via any gateway, directly fetchable by transaction ID with no specialized client required |

**The distinction that matters for the stated requirement:** Bitcoin, Ethereum, and Solana each carry data as a byproduct of a chain built for payments or general computation. None was designed around a one-time payment guaranteeing persistence without further action. Solana's rent-exemption comes closest in mechanism but still permits account closure. Arweave is the only one of the four built explicitly around the survive-the-author property, and its price is roughly what the difference in design intent would predict.
